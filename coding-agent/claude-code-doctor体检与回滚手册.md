# Claude Code /doctor 体检：改了什么、怎么回滚

## 背景

Claude Code 用久了会长出一堆"看不见的常驻开销"：装过就忘的 skill（任务专用指令文件）、试用过的插件（附加包）、旧安装残留、以及为了排查某个问题临时挂上去再没摘下来的 hook（事件触发脚本）。这些东西每次会话都在吃上下文，却没有任何地方会主动提醒你。

这次用 `/doctor` 做了一轮全量体检，最后把 65 个 skill、3 个插件停掉，卸掉一个旧版 npm 安装，并把默认权限模式切成 auto。本文记的是**判断依据**和**回滚方法**，不记具体停了哪些名字（名字在设置文件里自己看得到）。

## 核心判断

### 1. "没用过"要用两种证据交叉，不能只看一种

Claude Code 自己维护的使用计数器（`~/.claude.json` 里的 `skillUsage` / `pluginUsage`）是**终身累计**，从安装起只增不减，所以它回答的是"这辈子用过几次"，不回答"最近还在不在用"。

判断"最近在不在用"要看两个信号：
- 计数器里的 `lastUsedAt` 是否落在扫描窗口内
- 会话记录（`~/.claude/projects/*/*.jsonl`）里是否出现过对应的调用

两个都没有，才算窗口内未使用。有一个坑：插件计数器在安装、重新启用时会把 `lastUsedAt` 刷成当下，所以对于计数为 0 的插件，`lastUsedAt` 只是种子时间，不算证据。

### 2. 扫描窗口要看内容天数，不能看文件数

默认取"最近修改的 50 个会话文件"，结果 50 个全是当天的（子 agent 会拆出很多小文件），窗口只有 0.3 天，什么都判断不了。扩到 2000 个文件才覆盖到 23 天。**判断"未使用"之前先确认窗口够宽，否则宁可不下结论。**

### 3. 延迟加载的东西，"省 token"不是停用理由，"少一个要维护的连接"才是

MCP 服务器（外部工具连接）的工具定义默认是延迟加载的：上下文里只有工具名，schema 按需拉取。所以停用一个没人调用的 MCP 服务器，收益不是 token，而是少一个要认证、要更新的东西。反过来，一个窗口内哪怕只调用过两次的 MCP 服务器，因为本身几乎不占上下文，直接保留。

真正常驻每轮的是：skill/命令列表（每条的 name + description）、CLAUDE.md 全文、以及会输出内容的 hook。skill 列表还有一条隐性预算：约占上下文窗口的 1%，超了会被截断、skill 路由变差。在 1M 上下文模型下这个预算约 10k tokens，切到 200k 模型就只剩 2k，**同一套 skill 在不同模型下可能一个在预算内、一个已经爆掉**。

### 4. 权限变更必须和"清理"分开确认

停用扩展是减法，切默认权限模式和预批准命令是加法：它们扩大了"不问你就执行"的范围。两者混在一个确认里，用户点"全部清理"时就顺手放宽了权限。所以分成两个问题问，第二个问题必须逐条列出它会放行什么。

预批准只读命令这一项这次什么也没提：窗口内被拒的调用全是有副作用的（切分支、进容器、搜索），没有一个是纯读。顺带也确认了一个原则：`gh api *`、`git fetch/pull`、`curl` 这类看着像只读的命令都不能放行，前缀匹配拦不住 POST 和远端命令执行。

### 5. 自称"临时"的 hook 是最危险的常驻开销

体检发现一个 hook 脚本开头写着"临时探针，用完即删"，挂在每次发消息、每次停止、每个子 agent 结束上，每次都冷启动一次解释器、逐行数完整份会话记录，还把 hook 全量输入追加到日志。日志已经 100 多 MB，抓取目录 300 多 MB。

教训：**挂 hook 的时候就要给它写上到期日，或者放进一个专门的"临时"分组**，否则它会安静地跑几个月。这类改动 `/doctor` 只报警不动手，因为 hook 配置是用户有意为之的东西，删不删要用户拍板。

## 这次实际改动

全部写在用户级设置 `~/.claude/settings.json`，一个文件：

| 改动 | 字段 | 效果 |
|---|---|---|
| 停用未用 skill | `skillOverrides: {"<name>": "off", ...}` | 从 skill 列表里移除，不删文件 |
| 停用未用插件 | `enabledPlugins: {"<name>@<marketplace>": false}` | 插件不加载，缓存目录保留 |
| 默认权限模式 | `permissions.defaultMode: "auto"` | 安全分类器代替逐条弹窗；模型不支持时自动回退到 default 并提示 |

另外卸掉了 nvm 全局目录里残留的旧版 npm 安装。PATH 本来就优先解析原生安装，这个残留只是占地方，`which -a claude` 能看到两个来源就是信号。

### 写设置文件的安全习惯

skill 名、插件名都是从磁盘上读来的**不可信字符串**，不能拼进 shell 一行命令里（一个带 `$(...)` 的目录名就是命令注入）。正确做法：

1. 先把原文件备份（`settings.json.bak-doctor-<日期>`）
2. 用脚本把要合并的键值写成一个独立的 JSON 文件
3. 用 `jq --slurpfile` 合并到设置文件，写到 `mktemp` 生成的临时路径
4. `jq empty` 校验通过再 `mv` 覆盖

## 回滚手册

按需要的粒度选一种：

**整体回滚**：把备份复制回去。

```bash
cp ~/.claude/settings.json.bak-doctor-<日期> ~/.claude/settings.json
```

**只恢复某个 skill**：在 `skillOverrides` 里删掉对应那一行，下次会话生效。

**恢复某个插件**：`/plugin` 里重新开启，或把 `enabledPlugins` 里对应项改回 `true`。

**关掉 auto 模式**：删掉 `permissions.defaultMode` 这一行，回到逐条弹窗。

**恢复 npm 版安装**（一般没必要，原生版已是最新）：

```bash
npm -g install @anthropic-ai/claude-code
```

所有停用都是"不加载"而不是"删除"，skill 目录和插件缓存都还在磁盘上，回滚不需要重新下载任何东西。

## 关键知识点

- 使用计数器是终身累计；"最近是否在用"要靠 `lastUsedAt` 和会话记录交叉，插件的种子时间不算
- 扫描窗口按天数校验，不按文件数
- 延迟加载的 MCP 工具不占上下文，停用理由只能是"减少维护面"
- skill 列表预算约为上下文窗口的 1%，模型上下文缩小时预算同步缩小
- 清理（减法）和权限（加法）分开确认，权限问题逐条列出放行内容
- 只读命令放行只给精确匹配，不给前缀通配；`gh api`、`git fetch/pull`、`curl` 一律不放
- 停用写在用户级设置里，用 `skillOverrides` 与 `enabledPlugins`，不动 checked-in 文件
- 挂 hook 要给到期日，"临时探针"最容易变成永久开销
